# ECHOES

This repository contains the ECHOES project code, including data preparation, Compression--Think--Action SFT, privileged on-policy distillation with GRPO and PMF-guided weighting using verl, evaluation, and stateful deployment.

## Installation

Use Linux, Git, Python 3.11, and CUDA GPUs for training. Run commands from this directory. The package pins PyTorch, Transformers, and [verl](https://github.com/verl-project/verl/tree/482f86fd09959912c99c0acf2b90329f9e061da7). Training uses verl's FSDP engine, checkpoint manager, DataProto, GRPO advantages, and clipped policy objective.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

## Data preparation

Supply JSONL trajectories in `data/raw/trajectories.jsonl` and screenshots under `data/raw`. Each line contains:

| Field | Value |
|---|---|
| `trajectory_id` | Unique source trajectory identifier |
| `dataset` | Dataset name |
| `instruction` | Task instruction |
| `split` | `train`, `validation`, or `test`; omit to create grouped splits |
| `steps` | Chronologically ordered step objects |

Each step contains `image` and `action`. `image` is relative to the image root. Optional fields are `bbox` (xyxy), `width`, `height`, `memory_dependent` (boolean), and existing `compression`/`think` annotations. If supplied, `step_id` must start at zero and be contiguous. Action coordinates and bounding boxes use `[0,1]` by default; select `--coordinates pixels` or `--coordinates 1000` for other input scales.

| Action `type` | Additional fields |
|---|---|
| `CLICK`, `LONG_PRESS` | `x`, `y` |
| `TYPE` | `text` |
| `SCROLL` | `direction`: `up`, `down`, `left`, or `right` |
| `PRESS_BACK`, `PRESS_HOME`, `PRESS_RECENT`, `COMPLETE`, `IMPOSSIBLE` | None |

```bash
python -m echoes.data.prepare \
  --input data/raw/trajectories.jsonl \
  --image-root data/raw --output data/prepared
```

Preparation normalizes actions, replaces trajectory identifiers with hashes, re-encodes RGB screenshots, removes duplicate trajectories, and groups shared screenshots before splitting. Explicit splits are preserved and checked for overlap. The default selection contains 10,000 SFT steps and 9,500 OPD-RL steps. Use `--sft-steps` and `--rl-steps` to change these counts. Retained causal prefixes carry `trainable=false`; only selected steps contribute training losses. Outputs include `sft.jsonl`, `rl.jsonl`, `validation.jsonl`, `test.jsonl`, `manifest.json`, and `images/`.

Set `OPENAI_BASE_URL`, `OPENAI_API_KEY`, and `ANNOTATOR_MODEL` for the annotation service. Generate causal Compression and Think annotations with the student tokenizer's 128-token Compression limit:

```bash
python -m echoes.data.annotate \
  --input data/prepared/sft.jsonl \
  --output data/prepared/sft_annotated.jsonl \
  --image-root data/prepared \
  --model "$ANNOTATOR_MODEL" \
  --tokenizer Qwen/Qwen3-VL-8B-Instruct
```

Use `--resume` to continue an interrupted annotation job and `--reuse-existing` to validate and retain existing annotations. Each annotation request includes only the trajectory prefix through the current observation.

## SFT and OPD-RL

```bash
torchrun --standalone --nproc_per_node=8 \
  -m echoes.training.sft --config configs/sft.yaml

torchrun --standalone --nproc_per_node=8 \
  -m echoes.training.opd --config configs/opd.yaml
```

SFT supervises the full CTA target using the current image and preceding annotated Compression. OPD-RL samples eight responses per deployable state at temperature 1.0. Prefix Compressions are regenerated by the current student on recorded observations. The teacher receives the current screenshot and up to four preceding screenshots, without Compression, and scores the student's identical token prefixes. Full-vocabulary forward KL is averaged over CTA tokens; GRPO is averaged over responses. The teacher and mixture weight are fixed for six optimizer updates. The same latest student is evaluated under both views on a fixed validation subset at round boundaries to update the PMF schedule.

Model paths, image resolution, optimizer settings, training length, reward coefficients, and validation size are configured in the YAML files. Override individual settings with `--set`; use `--model`, `--train`, `--validation`, `--image-root`, and `--output` for path changes. The default model is Qwen3-VL-8B-Instruct.

```bash
torchrun --standalone --nproc_per_node=8 \
  -m echoes.training.opd --config configs/opd.yaml \
  --resume checkpoints/opd/step_00000006
```

Checkpoints contain model, optimizer, scheduler, RNG, data fingerprints, and PMF state. OPD checkpoints are saved at round boundaries. Resume with the same configuration and GPU count. Each checkpoint's `huggingface/` directory and the run's `final/` directory can be loaded for inference. `metrics.jsonl` records losses, rewards, validation scores, mixture weights, rollout/update times, and teacher-refresh times.

Training ablations use `--set schedule.mode=rl_only`, `opd_only`, `linear`, or `fixed`. For fixed mixing, also set `schedule.fixed_weight`. Set `training.steps_per_round` to change the refresh interval and `schedule.lambda_min`/`schedule.lambda_max` to change the PMF bounds. Use a separate `--output` for each run.

## GUI evaluation

```bash
python -m echoes.evaluation.gui \
  --data data/prepared/test.jsonl --image-root data/prepared \
  --model checkpoints/opd/final --output results/gui

python -m echoes.evaluation.gui \
  --data data/prepared/test.jsonl --image-root data/prepared \
  --model checkpoints/opd/final --view paired --output results/paired
```

Evaluation replays recorded screenshots in order. Deployment inputs contain only the task, current screenshot, and self-generated Compression. `--view paired` evaluates the same checkpoint and instances under deployable and privileged inputs. Use `--split validation` when evaluating a validation file.

The unified nine-action protocol reports TM/action-type accuracy, EM/step accuracy, grounding accuracy, trajectory exact match, memory-dependency groups, trajectory-length groups, input tokens, and latency. Point actions use reference-box containment when a box is supplied, otherwise normalized Euclidean distance with `--point-tolerance 0.14`. Text matching defaults to normalized exact matching; `--text-match anls --anls-threshold 0.5` enables edit-similarity matching. Scroll matching uses exact direction. The selected protocol is saved in `metrics.json`.

Memory interventions use `--memory-mode none`, `shuffle`, `stale`, or `naive`; recursive Compression is the default. Shuffled memory comes from another trajectory's model-generated states, and stale memory defaults to a two-step lag. Generic summarization costs are included in naive-mode efficiency measurements.

```bash
python -m echoes.evaluation.gui \
  --data data/prepared/test.jsonl --image-root data/prepared \
  --model checkpoints/sft/final --output results/sft

python -m echoes.evaluation.bootstrap \
  --first results/gui/deployable_steps.jsonl \
  --second results/sft/deployable_steps.jsonl \
  --output results/bootstrap.json --resamples 10000
```

Bootstrap inputs must contain the same steps and reference actions. The output contains the paired EM difference, trajectory-bootstrap confidence interval, centered two-sided bootstrap p-value, and sign-tail probability.

## ECHOESBMK

Create `data/raw/diagnostic_queries.jsonl` with `task`, `question`, `answer`, `human_verified=true`, and `image` for single-screen queries or ordered `images` for before/after queries. Image paths are relative to `--image-root`. Both element-level tasks also require a reference `bbox`.

| `task` | Reference `answer` |
|---|---|
| `bbox_to_function` | Functional description, or an MCQ choice key |
| `semantic_to_bbox` | A point derived from the supplied reference `bbox` |
| `active_tab` | Active tab label |
| `foreground_layer` | Object with boolean `present` and string `description` |
| `blocking_state` | Object with boolean `blocked` |
| `screen_selection` | Selected-item list or item-to-value object |
| `screen_state_diff` | Before-to-after change description, or an MCQ choice key |

MCQ records include `choices`, an object mapping uppercase letters to distinct answers. To construct alternatives from a reviewed candidate list, supply `distractors` and `distractors_human_verified=true`. The `human_verified` field certifies review of the complete question and answer, including supplied choices.

```bash
python -m echoes.data.benchmark \
  --input data/raw/diagnostic_queries.jsonl --image-root data/raw \
  --output data/diagnostic \
  --exclude-trajectories data/prepared/train.jsonl data/prepared/validation.jsonl

python -m echoes.evaluation.benchmark \
  --data data/diagnostic/benchmark.jsonl --image-root data/diagnostic \
  --model checkpoints/opd/final --output results/diagnostic \
  --judge-base-url "$OPENAI_BASE_URL" --judge-model "$JUDGE_MODEL"
```

Set `JUDGE_MODEL` and `ECHOES_JUDGE_API_KEY` for free-text scoring. Free-text function and state-difference answers require `--judge-base-url` and `--judge-model`; omit these two options for MCQ-only description scoring. Grounding uses region hit rate; screen-state judgments use accuracy or selected-value matching. Parse failures count as incorrect and are reported separately.

The four L2 tasks additionally use cached summaries generated by the evaluated model. Memory replay receives the summary and question without any screenshot. `PMF_gap_macro` clips each task's vision-minus-memory score to zero before averaging the four task gaps. Use `--vision-only` for direct perception evaluation alone.

To construct queries from reviewed screen records, use `--mode screens`. A screen record contains `image` and any of: `elements` with `bbox`, `function`, and optional localization `request`; `active_tab` with `answer`; `foreground_layer` with `present`/`description`; `blocking_states` with `question`/`blocked`; `screen_selection` with `selected`; and `transitions` with `next_image`/`description`. Each retained annotation requires `human_verified=true`. Screen annotations with MCQ `choices` also require `choices_human_verified=true` and `correct_choice`.

## Sokoban transfer

Install the dependencies of the official [MageBench](https://github.com/microsoft/MageBench) environment and set `MAGEBENCH_ROOT` to its checkout directory. The scenarios file is a JSON array of scenario paths relative to its `resources/` directory.

```bash
python -m echoes.evaluation.sokoban \
  --magebench-root "$MAGEBENCH_ROOT" \
  --scenarios "$MAGEBENCH_ROOT/resources/Sokoban_all.json" \
  --model checkpoints/opd/final --output results/sokoban
```

This entry point executes native environment moves and records native scores, normalized scores, solved-task counts, and efficiency. Use identical scenario, resolution, step-budget, and memory settings for checkpoint comparisons.

## Stateful deployment

```python
from echoes.agent import CTAAgent
from echoes.inference import Policy

agent = CTAAgent(Policy("checkpoints/opd/final"), "Open the calendar and create a reminder.")
decision = agent.act("current.png")
action = decision["action"]
```

Execute `action` in the GUI environment, then call `agent.act` with the new screenshot. The agent retains only its latest Compression. Call `agent.reset` for a new task.
